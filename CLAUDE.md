# Shabbat Display

Echo Show replacement for Avi's home: a full-screen, hands-off information display that runs on a spare Windows PC/laptop or a Raspberry Pi and updates itself on timers through Shabbat. Left alone it changes only on a schedule. On weekdays Avi can tap it (iPad) or click it (mouse) to open detail panels and swipe between scenes; it returns to rotation 2 minutes after the last input, and all interaction is off in `body.holy` and in screen-saver mode. No camera or motion input. No microphone either, with one exception Avi asked for in Nov 2026: the iPad app's voice assistant, which is opt-in on the iPad and off on Shabbat and Yom Tov (see `apple/` below). Design: `docs/superpowers/specs/2026-10-29-interactive-display-design.md`.

Owner preferences:
- Builds and runs locally on his Windows PC. Setup must stay easy on both Windows and Raspberry Pi OS: one setup script per platform, no manual config files to hand-edit before first run.
- No GitHub Actions or CI workflows.
- Python standard library only on the server, so there is nothing to pip install.

## Architecture

- `server.py`: stdlib HTTP server on `127.0.0.1:8765`.
  - One background thread per data source, each on its own refresh interval (the `SOURCES` table).
  - Keeps the last good result per source in memory and in `cache.json`. Failures keep the old data, are recorded in `meta`, and retry with backoff.
  - Serves `index.html` at `/`, all data at `/api/state`, and `/health` and `/fonts/*`.
  - On-demand endpoints for the panels, each behind `cached(key, ttl, fn)` (in memory): `/api/article?url=` (only http(s) URLs that are a `link` in one of the `ARTICLE_FEEDS`, else 404; text from `<p>`s via `extract_article()`; on failure the feed summary, retried after 60 s; Google News backup links aren't fetched; "cut off" only for NYT pages marked `isAccessibleForFree:false`), `/api/game?id=` (ASCII digits only; statsapi v1.1 live feed → `norm_boxscore()`; 25 s cache while live or not started, 10 min otherwise). `cached()` takes a ttl or a function of the value, and drops expired entries on each store, `/api/forecast` (Open-Meteo + air quality + all NWS periods + calendar candle/havdalah marks → `build_forecast()`), `/api/radar` (NWS KOKX loop GIF, 5 min).
  - Household config (design: `docs/superpowers/specs/2026-11-07-display-manager-design.md`), set from the Display Manager app:
    - `household.json` (gitignored, written only by the server, read again when its mtime changes): `sports` (MLB plus every key in `LEAGUES`: `on`, `teams` as `{id, abbr, name}`, `favorite`), `business` (`on`, `watchlist` as `{symbol, name}`, `news` switches), `default_rotation` and `screens` (name → `rotation` or null for the house default, `launcher`, `saved`, `mode`, `saver`, `local`), `secrets.nyt_cookie`. `household()` returns a copy; `save_household()` writes `household.json.bak` and then `household.json`, each fsynced and atomic. `_fill_household()` repairs any bad shape (bad items dropped, missing parts from the defaults), so a hand-edited file can't break `/api/state`. A file that can't be read is never used and never overwritten: the last good copy in memory, else the `.bak`, else the defaults stand in, and the next save first renames it to `household.json.bad-<time>` (both logged). `state_json()` never fails: on any error it answers with the house defaults, so no screen drops to preview data. After a save, `wake(key)` sets that source's event in `WAKE`, so `run_source()` refreshes at once (a league switched on, a stock added on a weekend); a switched-off league also checks every minute. On first start `default_household()` builds it from today's display: MLB on with the Yankees, house rotation `shul, yankees, mlb, news, israel, business`, and only `DESKTOP-H72VKDJ` (`SERVER_PC`) gets a rotation with `agenda`.
    - `manage-key.txt` (gitignored): the access code, made by `manage_key()` at startup. `setup-windows.ps1` prints it at the end on the server PC.
    - `/api/manage/*` (`manage_route()`, header `X-Manage-Key`, else 401; a bad body is 400 with a plain sentence): GET `status` (feeds' meta, `shul_status()`, screens with last check-in), `household` (no secrets, only `nyt_signed_in`/`agenda_set`, plus `leagues` and `scene_catalog()`), `log?lines=`, `teams?league=&q=` (`team_search()`), `stocks?q=` (`stock_search()`); POST `sports` (switching a league on adds its pair to the house rotation, and switched off to custom rotations), `business`, `rotation` (`screen` null = house default; `rotation` null = use the house default), `screen` (mode and saver options; marks it `saved`), `nyt` (`""` signs out), `shul-update`, `restart` (exits; the launcher restarts it).
    - Screens: the page sends `?screen=NAME` (`valid_screen()`: letters, digits, space, `._'-`, up to 40). `state_json(screen)` records the check-in (`seen`, in memory; a new name joins `household.json`), returns that screen's `config.rotation`, `config.sports`, `config.business_news`, and leaves `data.agenda` out unless the screen's rotation has `agenda`. No name gets the house default. `&preview=1` (the app's live view) shows a screen without checking in, so it never adds or refreshes a screen.
    - `/api/screen-settings?screen=&mode=&minutes=&lock=&shabbat=` (no key, nothing secret; an older launcher's `awake` counts as `shabbat`): a launcher checks in with its own settings; until the screen is saved in the app, the answer echoes them back, so upgrading a PC never changes what it does. A screen's `mode` is `always`, `saver` (Windows' screen saver is the Shabbat Display) or `off`; `saver` is `{minutes, lock, shabbat}` (`_fix_saver()`; an old `keep_awake` becomes `shabbat`). The answer also carries `holy` (`holy_spans()`): each coming Shabbat or Yom Tov as `{start, end}`, Hebcal's candle lighting to the next havdalah, with a second night's candles in the same span.
  - `nyt_cookie` (secret, like `agenda_ics`): `nyt_cookie()` is the one set from the app (`secrets.nyt_cookie`; `""` means signed out in the app and wins over settings.json; `null` means never set), else settings.json's. Sent only to nytimes.com hosts by `article_headers()`. nytimes.com and timesofisrael.com answer 403 to non-browser article requests at times; that is bot protection and is not worked around.
  - Shul (Bnai Yeshurun) source, `shul` in `SOURCES` (design: `docs/superpowers/specs/2026-10-30-shul-tab-design.md`):
    - `fetch_shul()` runs hourly but fetches only when `shul_due()`. That is: nothing is stored or a stored file is missing; or on Friday, or any day with candle lighting (Erev Yom Tov), from 12:00 until candle lighting (`todays_candles()`, else 18:00) while the bulletin is dated before today; or 8:00–20:00 while the chart is more than 6 days old. Never on Saturday.
    - After a failure it retries no sooner than hourly (`RETRY_FLOOR` in `retry_wait()`).
    - One fetch runs at a time (`_shul_lock`). `/api/shul-update` answers 409 when a fetch is already running.
    - It reads `/minyan`, `/bulletin` and `/monthlycalendar`, and `shul_links()` picks the chart PNG, the newest bulletin PDF and the calendar JPGs (only `images.shulcloud.com`).
    - It downloads only URLs that changed into `shul/` (gitignored, served at `/shul/<name>`, names `[A-Za-z0-9._-]` only), and deletes files the new value no longer uses. Dates come from file names (`file_date()`).
    - `pdf_pages()` is a small stdlib PDF text reader (Flate, Tj/TJ, ToUnicode). `shabbat_times()` reads the bulletin's "Shabbat Times" box into rows `{label, time, he}` and notes `{text, after}`, using column positions measured on the real Word-made bulletin. It returns None rather than a partial table: no box, no Candle or Ends row, or Latin text in a row's Hebrew column (the box's right edge is capped at x 316). A line without a clock time becomes a note: its English left to right, then its Hebrew right to left.
    - Every request uses `SHUL_UA = "ShabbatDisplay/1.0 (personal home display)"`. The site 406s generic tools (curl, Python) but answers this. Never switch to a browser User-Agent to get past a refusal; a refusal just keeps the last files.
    - `/api/shul-update` (127.0.0.1 only) runs a forced fetch. `python server.py --update-shul` (`update-shul.bat`/`.sh`) calls it, or fetches in-process if the server isn't running.
  - `python server.py --check` fetches every source once and prints OK/FAIL.
  - Defaults live in the `CONFIG` dict at the top of the file (location, candle-lighting minutes, havdalah method, team, dimming, rotation, bind address). `settings.json` (gitignored, created by setup from `settings.example.json`) overrides them at startup in `load_settings()`; dict values such as `rotation_seconds` merge.
  - `python server.py --setting KEY` prints one resolved setting (used by `setup-pi.sh` for `tzid`).
- `index.html`: single page with no build step, all CSS and JS inline.
  - Polls `/api/state` every 20 seconds.
  - Designed on a 120×67.5 rem canvas (16:9), scaled by setting the root font-size from the viewport. On screens taller than 16:9 (the iPad, 16:10 laptops) the canvas takes the full height (`height:100%`): the scene area grows and `.side` spreads out (`max-aspect-ratio:17/10`). A 16:9 screen is unchanged.
  - On a touch screen (`pointer: coarse`, or `?fullpanel=1`) `body.fullpanel` makes panels cover the whole screen at `zoom:1.3`.
  - Fixed regions: a left column (clock, dates, weather, hourly, 5-day) and a bottom band (Shabbat/Yom Tov box and the zmanim "sky bar").
  - The stage rotates between the scenes in `rotationList()`: `config.rotation` from the server (this screen's), else today's built-in `agenda, shul, yankees, mlb, news, israel`. `buildOrder()` drops scenes with nothing to show (a league switched off or out of season, MLB off, no markets). `withLive()` repeats each favorite team's scene every other turn while it plays, and `#chips` holds a live chip per favorite (`game` panel for MLB, `score` for the rest), hidden on that team's own scene. Other leagues (`registerSports()`, from `config.sports`) get `<key>_team` (favorite's live/last/next card with the by-period line, standings group, team and league news) and `<key>` (today's or yesterday's scores, chosen teams first, league news). `PANELS.score` shows a game from the state with no request. `business`: index tiles, the watchlist, and NYT Business/CNBC headlines; the note says "Delayed" with the time, or "Market closed" with whose close it is (`last_trade`). The `yankees` scene follows the MLB favorite (`config.team_abbr`); its news column is MLB news unless the favorite is the Yankees. The scenes `agenda`, `shul`, `yankees`, `mlb`, `news` and `israel` are the original ones. `shul` shows the weekly chart image on weekdays, with Calendar/Bulletin buttons (`PANELS.shulimg`, and `PANELS.bulletin`, which uses an iframe on the PC and a link to Safari's viewer under `body.fullpanel`). It shows the bulletin's Shabbat Times (`shulShabbatOn()`) in `body.holy`, and also on the day of candle lighting (Friday or Erev Yom Tov) as soon as this week's bulletin is in and readable, with Weekly chart/Calendar/Bulletin buttons underneath until candle lighting. `bulletinCurrent()` checks the bulletin's date against `shabbatSpan()`: from the day of the candle lighting that begins (or began) this Shabbat or Yom Tov through the day of havdalah. In `body.holy` the times are shown only when `bulletinCurrent()` holds. Otherwise, or when the times couldn't be read, it shows Hebcal candles/havdalah with the reason and "Shul times unavailable". `fitShabbat()` shrinks a long table (down to 60%) and then says there are more times in the bulletin. The title is "Yom Tov times" on Yom Tov. Images are inverted to suit the dark theme. Stale notes cover a chart older than 6 days and a bulletin that isn't this Shabbat's. During a live Yankees game the Yankees scene repeats every other turn and a live score chip appears on the other scenes.
  - `agenda` (today plus the next non-Shabbat day) and the "Next" line under the clock show only when `agenda_ics` is set, this screen's rotation has `agenda`, and not in `body.holy` (`agendaOn()`). If Shabbat starts while the agenda is up, `renderAll()` advances off it immediately.
  - Shabbat/Yom Tov mode (`body.holy`) runs from the last candle-lighting item until havdalah, based on Hebcal calendar items.
  - Overnight dimming uses a black overlay. A small pixel shift every 10 minutes guards against burn-in. The page reloads every 6 hours if `/health` answers. It requests a Screen Wake Lock.
  - Opened as a file with no server, it renders built-in demo data (`makeDemo()`, including `demo_panels`) for layout work.
  - Interaction: elements carry `data-tap="article|game|forecast"` (plus `data-key`/`data-link` or `data-id`), scene tabs `data-scene`, forecast day rows `data-toggle`. Pointer Events on `document`: a tap is under 10 px / 500 ms; a swipe starts in `.scene-wrap`/`.stage-head` and is ≥ 80 px, mostly horizontal. `PANELS[kind] = {load, render, refreshMs?, shouldRefresh?}` render into `#panel` inside `.scene-wrap` (the scenes repaint underneath and never touch it). `lastInput` pauses rotation; `tick()` ends the interaction after `idleMs()` (2 min; `?debug=1` + `IDLE_MS_OVERRIDE`) or when `interactive()` turns false. The pointer is hidden (`cursor:none`) until the mouse moves. Hidden scene layers have `pointer-events:none`.
- `launcher.pyw`: supervisor for Windows and Linux.
  - This screen's name: `screen_name` in settings.json, else the PC's name (`screen_name()`). The page opens at `page_url()` with `?screen=`.
  - Every minute `fetch_screen_settings()` asks `/api/screen-settings` (sending this PC's own settings) and caches the answer in gitignored `screen-settings.json`. `screen_setting()` reads mode and screen-saver options from it, else settings.json, else (mode) the `--screensaver` flag. `main()` runs `always_loop()` or, for mode `saver` or `off`, `windows_saver_loop()`; each returns, with its windows closed, when the mode changes, so the app can switch a PC with nobody at it. The mutex and log file stay those of the startup flag. Profiles come from `profile_for(mode)`.
  - `server_url` in settings.json (`display_url()`): the PC shows another machine's display and never starts `server.py`; the browser opens only once that server's `/health` answers (full time), and the screen saver doesn't open while it's down.
  - Starts the server and Chrome, Edge or Chromium in `--kiosk` mode with its own profile in `browser-profile/`, and restarts either one if it exits. Reads `port` from `settings.json`.
  - Single instance (a named mutex on Windows, `flock` on `launcher.lock` on Linux).
  - Before each browser start it marks the profile as cleanly exited, and on Linux removes stale `Singleton*` locks, so a power cut never leaves a restore-pages bubble or a refused profile.
  - Keeps the screen awake with `SetThreadExecutionState` on Windows and `xset` on X11. Under Wayland it relies on `setup-pi.sh` turning blanking off with `raspi-config`.
  - Mode `saver` (Windows; `start-screensaver.bat`, or option 2 in `setup-windows.ps1`; design: `docs/superpowers/specs/2026-11-08-windows-screensaver-design.md`): Windows' own screen saver is `saver\ShabbatDisplay.scr` (gitignored, built by `build-saver.bat`). `windows_saver_loop()` opens no browser. Every 30 s it:
    - writes `HKCU\Control Panel\Desktop` the way Control Panel does (`SCRNSAVE.EXE` by `winreg`, the rest by `SystemParametersInfoW`), only values that differ (`saver_registry()`, `registry_changes()`). `SCRNSAVE.EXE` gets Windows separators and, with a space in the path, the 8.3 short path (`scr_registry_path()`). Over Shabbat with the Shabbat switch on, `ScreenSaverIsSecure` is 0, so nothing locks. Mode `off` (and always on) turns Windows' screen saver off only if it is ours.
    - writes `saver\saver.json` (`{url, screen, shabbat, holy}`, only when it changes) for the `.scr`. The holy spans come from the cached answer, so they survive the server being down.
    - with the Shabbat switch on, holds `ES_SYSTEM_REQUIRED` from midnight of the candle-lighting day to havdalah (`shabbat_day()`), never `ES_DISPLAY_REQUIRED` (that would stop the screen saver from starting), and raises the plugged-in screen-off time to the wait plus 20 minutes if it would come first.
    - logs once if the `.scr` is missing or a policy (`HKCU\Software\Policies\...\Control Panel\Desktop`) sets screen-saver values.
    - It restores a brightness left in `brightness-before-saver.txt` by the old launcher saver, which opened kiosk browsers and is gone.
- `manager/Saver` (`ShabbatDisplay.scr`): WinForms + WebView2, single-file and self-contained (53 MB compressed). `/c` or nothing: "managed from the app"; `/p HWND`: a small "Shabbat Display" preview; `/s`: one borderless topmost window per monitor (primary first), each showing `saver.json`'s page with `?screen=&saver=1&shift=N` so each monitor starts on a different scene. Its logic (`SaverLaunch`, `SaverConfig`, `InputGate`) is in `Manager.Core` and tested. Any new input (`GetLastInputInfo`) hides the windows and exits at once; over Shabbat (`IsHoly`, with the switch on) input and every close but Windows shutting down are ignored, and input made on Shabbat doesn't count after havdalah. It holds the screens on from midnight of the candle-lighting day (`HoldScreens`). Rereads `saver.json` every minute. When the page can't load: a clock and "Display not reachable", retried every 30 s. Its mutex is `Local\ShabbatDisplayScreenSaver`; `ShabbatDisplaySaver` is the launcher's.
- `manager/`: the Display Manager, a WinUI 3 app for Avi's PC (design: `docs/superpowers/specs/2026-11-07-display-manager-design.md`). .NET 10 (`net10.0-windows10.0.19041.0`), Windows App SDK 2.6.5, unpackaged and self-contained (`EnableMsixTooling` is needed or publish leaves out the app's `.pri` and XAML, and the exe crashes in `Microsoft.UI.Xaml.dll`). `build-manager.bat` tests, builds the screen saver (`build-saver.bat`), publishes to `dist\manager` and adds a Start-menu shortcut; both pick a .NET 10 SDK with `dotnet-sdk.bat`. Export-ignored, so never in the installer zip.
  - `Manager.Core` (no UI, tested): `ManageClient` (every call returns `Result<T>`; errors are sentences: 401 "The access code was refused…", no answer "The display server isn't answering…", 404 "…needs updating…", else the server's `error`). JSON is snake_case, and ints accept `10.0`. Bodies go as a string with a Content-Length, because the server reads exactly that many bytes. `ServerFinder` (remembered address in `%LOCALAPPDATA%\ShabbatDisplayManager\server.txt`, then 100.98.145.119, DESKTOP-H72VKDJ, 192.168.4.109; `/health`, 2 s each). `CredentialStore` (the access code in Windows Credential Manager, target `ShabbatDisplayManager`, nowhere else). `StatusSummary`, `RotationEditor`, `Watchlist`, `LeagueRules`, `ShulRows`.
  - `App`: `AppState.Call()` wraps every request; a 401 opens `ConnectDialog` again, and a server that stopped answering is looked for again (each retries once). Pages are built in code-behind. Edits stay on the page until Save, which shows "Saved. Screens update within a minute." Live view shows the display page in WebView2 (its own data folder, `WebView2-Live`): the house rotation, or a screen via `LiveView.PageUrl()` with `preview=1`. The NYT page signs in with WebView2 (data in `%LOCALAPPDATA%\ShabbatDisplayManager\WebView2`), reading `NYT-S` after each navigation, or takes a pasted value; the cookie is never shown.
- iPad as a second screen: set `"bind": "0.0.0.0"` and a Windows firewall rule for TCP 8765 from `LocalSubnet`. Then open `http://<ip>:8765` in Safari and add it to the Home Screen; Apple's web-app meta tags make that full screen. Needs iPadOS 14.5+, because the page uses `??` and flex `gap`. SwiftUI, iPadOS 17+, `com.avifrischlaw.shabbatdisplay`, project made by `xcodegen generate` from `apple/project.yml` (the `.xcodeproj` and Info.plist are gitignored). Export-ignored, so never in the installer zip.
  - It shows this server's page in a `WKWebView` (`DisplayWebView`), so the display stays one codebase. First run asks for the computer's address and the screen's name (`SetupView`; port 8765 assumed); holding the top-left corner for 2 s opens it again, except on Shabbat and Yom Tov. Plain http works through `NSAllowsLocalNetworking` (IP addresses and local names, not a `.ts.net` name).
  - `AppModel` asks `/health` every 20 s. While the page isn't up it shows a clock and "Display not reachable" (`WaitingView`) and loads the page as soon as the server answers; it also reloads when iPadOS drops the page's process. The screen stays on (`isIdleTimerDisabled`) while the app is in front. Navigation off the server is refused; a `target="_blank"` link (the bulletin) opens over the display with a Back button and closes after 5 minutes.
  - Shabbat rule (`HolySpans`, tested): every 15 min it reads the calendar from `/api/state?screen=…&preview=1` (no check-in; never `/api/screen-settings`, which would mark the iPad as having a launcher) and keeps the candle-lighting and havdalah marks in UserDefaults. `HolyState` is `.holy`, `.weekday(nextCandles:)` or `.unknown`; a calendar with no candle lighting ahead is `.unknown`, never weekday. Anything that must be off on Shabbat (the microphone, speech and music of the later phases) must ask `weekdayForCertain`.
  - Voice (phase 2; off until "Listen for requests" is switched on in the app's settings, which is when iPadOS asks for the microphone). `VoiceController` owns it. `Listener`: `AVAudioEngine` tap → a loudness check with a noise floor → only a stretch of sound (plus the 0.8 s before it, ended by 1.2 s of quiet or 20 s) goes to `SFSpeechRecognizer` (on-device when the iPad supports it). `WakePhrase` (tested) finds the phrase ("hey display", settable; "hay/hi/a/okay display" count) and returns the words after it; the phrase alone opens an 8 s window for the request. A chime marks the phrase. The request goes to the server's `/api/assistant` with the running timers and the last 3 exchanges (3 min); the answer is spoken (`Sounds`, `AVSpeechSynthesizer`) with the listener muted, and its `actions` set or cancel `KitchenTimers` (tested; kept in UserDefaults; ring = three beeps every 4 s and the name once; "stop" and similar words, or a tap, quiet it; quiet by itself after 3 min). `VoiceOverlay` draws the timers (bottom right), the heard/answer bubble and a small mic mark while waiting.

The chip above the timers has pause, next and stop. Never touches the player until music is first asked for, and never in the simulator. ## Testing

- `python server.py --check`: tests every source.
- `python -m unittest discover -s tests`: stdlib unit tests for the on-demand endpoints (`tests/test_server.py`) and the shul source (`tests/test_shul.py`). Fixtures are in `tests/fixtures/`. The article and shul pages there are made up, with real page structure, not saved copies. Synthetic bulletin PDFs come from `tests/pdfmaker.py`, laid out like the real Shabbat Times box.
- `python server.py --update-shul`: fetches the shul's files now and prints what it got, including the number of Shabbat Times rows. Compare a new bulletin's rows to its page 2 if the layout ever changes. On Avi's PC `python` in PowerShell is the Store stub; use `C:\msys64\mingw64\bin\python.exe`.
- URL parameters:
  - `?at=2026-10-30T15:10`: fakes the clock. Note this affects only the client side, since the server still fetches for the real "now".
  - `?scene=mlb&hold=1`: pins one scene and stops the rotation.
  - `?shift=N`: starts the rotation N scenes in (the screen saver's monitors).
- Screenshots: from the cloud session, Playwright was used at 1920×1080, 1366×768 and 1440×900. All three fit.
- Display Manager app: `dotnet test manager\Manager.Tests` (xUnit, the UI-free `Manager.Core`). To try the app without touching the real display, run the real request handler on another port with a temporary `HOUSEHOLD_FILE`/`KEY_FILE` and no source threads (as `tests/test_manage.py` does), and put its address in `%LOCALAPPDATA%\ShabbatDisplayManager\server.txt`. The app can be driven with Windows UI Automation (every control has a name) and captured with `PrintWindow`.
- Never tested on real hardware: `launcher.pyw`, the kiosk flags, `SetThreadExecutionState`, the wake lock, both setup scripts, and labwc honoring XDG autostart on Pi OS. Verify these first.

## Design

- Dark navy base (`--bg #0D1726`), warm off-white text, gold accent `#E5BA5E` for Hebrew and Shabbat items, sky blue for weather.
- In Shabbat mode the background tint shifts warm. Otherwise the tint follows time of day.
- The zmanim bar is a day-length gradient (night → dawn → day → sunset → night). Labels alternate above and below, a sun or moon marker shows the current time, and the next zman is highlighted in gold.
- Headlines use the serif face. Column lists drop any item that would be clipped (`fitColumns()`).
